# Эксперимент ⚡A: будет ли работать выбор модели в Agent mode

Изначальная задача была просто «интересно, заработает ли эта функция» — в чате
arena.ai после начала диалога появляется третья иконкаcomposer'а: молния с
маленькой буквой `A`. Эксперимент занял версии 1.4 → 1.9 и дал честный
отрицательный ответ. Ниже — хронология, она же отличная иллюстрация того, почему
JS, внедряемый в WebView, надо проверять линтером.

## Хронология

| Версия | Найденная проблема | Исправление |
|---|---|---|
| 1.4 | `EXPERIMENT_JS` не запускался **вообще**: при склейке Java-строк получилось `e.closest('…,'+[class*=composer]')` → `SyntaxError: Unexpected token '*='`. Тёмная тема маскировала поломку, т.к. шла отдельным вызовом. | Исправлена склейка. |
| 1.5 | — | Добавлен `check_js.py`: `node --check` по каждому JS перед компиляцией, сборка падает при ошибке. Повторный запуск и на `onPageCommitVisible`, и на `onPageFinished`; авто-диагностика Toast; копирование диагностики в буфер. |
| 1.6 | `/agent` — **отдельный маршрут**, кнопка там называется `aria-label="Mode"`, а не `Modality: Auto`. Слово «mode» не содержит «model», поэтому цель не находилась. Плюс SPA-переход не вызывает `onPageFinished`. | Точный селектор, хуки на `history.pushState/replaceState/popstate`, `MutationObserver` без фильтра атрибутов, тик раз в 2 с. |
| 1.7 | Обводка попадала **не на ту кнопку**: ✳ (`Modality: Auto`) набирала больше очков, чем ⚡A. Меню с диагностикой **никогда не открывалось** — `onBackPressed()` безусловно уходил `web.goBack()`, а SPA-история почти всегда непустая. | `modality` исключён, приоритет у zap-иконки + буквы `A`; добавлена плавающая кнопка ⚡, двойной Back как запасной путь. |
| 1.8 | Диагностика с устройства дала точный ответ: `Mode [disabled=false]` и `⚡ Model [disabled=true]`. `exact()` возвращал `Mode` первым, поэтому разблокировка доставалась не той кнопке. | Приоритет `button[aria-label="Model"]`, обводка снимается со всех остальных, `disabled` снимается при каждом ререндере React. |
| 1.9 | Кнопка стала `disabled=false` и обвелась, но **нажатие ничего не открывало**. | Добавлены инспекция React-props и «6 способов открыть». |

## Результат проверки

```
{"done":true,"opened":false,"attempts":[
 {"step":"native .click()","popovers":0,"expanded":"false","state":"closed"},
 {"step":"mouse chain",  "popovers":0,"expanded":"false","state":"closed"},
 {"step":"touch chain",  "popovers":0,"expanded":"false","state":"closed"},
 {"step":"Enter",        "popovers":0,"expanded":"false","state":"closed"},
 {"step":"Space",        "popovers":0,"expanded":"false","state":"closed"},
 {"step":"parent click", "popovers":0,"expanded":"false","state":"closed"}]}
```

Ни `aria-expanded`, ни `data-state`, ни число поповеров не изменились. Если бы у
кнопки был `onClick`, как минимум `.click()` или `Enter` перевели бы `data-state`
в `open` — значит обработчик **не назначен вовсе**.

## Причина

В JS-чанках сайта:

```js
const enabled = !0 === featureFlag("agent-model-selector");
```

Флаг `agent-model-selector` описан в схеме как `boolean()`, но **отсутствует в
серверном RSC-пейлоаде** (`/` и `/agent`) для этого аккаунта → `false`.
Компонент `ModelSelectorTrigger` получает `triggerDisabled` / `disabledFlags` и не
вешает обработчик открытия. Снятие DOM-атрибута `disabled` даёт визуально
активную кнопку, но не включает функцию: состояние живёт в React и на сервере.

**Вывод:** в текущей конфигурации аккаунта функция не работает, и обойти это из
WebView нельзя. Если arena.ai когда-нибудь включит флаг, селектор заработает и без
каких-либо клиентских костылей.

## Что осталось в коде 2.0

Ничего из эксперимента. Все `EXPERIMENT_*` константы, обводка
`[data-arena-exp]`, плавающая кнопка, диагностика и пункты меню удалены.
`MainActivity.java` сократился с ~1400 до 670 строк, `check_js.py` проверяет
только `DARK_JS`, размер APK вернулся к 484 933 B (как у принятой 1.3).
Сохранился один полезный багфикс: меню открывается двойным нажатием «Назад».

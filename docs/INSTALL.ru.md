## Итог эксперимента (закрыт)

Проверка «🧪 Попробовать открыть (6 способов)» на 1.9 вернула:

```json
{"done":true,"opened":false,"attempts":[
 {"step":"native .click()","popovers":0,"expanded":"false","state":"closed"},
 {"step":"mouse chain",  "popovers":0,"expanded":"false","state":"closed"},
 {"step":"touch chain",  "popovers":0,"expanded":"false","state":"closed"},
 {"step":"Enter",        "popovers":0,"expanded":"false","state":"closed"},
 {"step":"Space",        "popovers":0,"expanded":"false","state":"closed"},
 {"step":"parent click", "popovers":0,"expanded":"false","state":"closed"}]}
```

Ни один способ не изменил ни число поповеров, ни `aria-expanded`, ни
`data-state`. Если бы у кнопки был `onClick`, как минимум `.click()` или `Enter`
перевели бы `data-state` в `open`. Вывод: **обработчик открытия не назначен
совсем**, потому что серверный фича-флаг `agent-model-selector` для этого
аккаунта выключен. Клиентская разблокировка DOM-атрибута `disabled` даёт
визуально активную кнопку, но не включает саму функцию.

Это и есть ответ на исходный вопрос «интересно, будет ли эта функция работать»:
**в текущей конфигурации аккаунта — нет**. Обойти из WebView нельзя: состояние
живёт в React/на сервере, а не в разметке.

Приложение при этом полностью рабочее (полный экран, тёмная тема, космическая
иконка, та же подпись и пакет). Чтобы убрать фиолетовую обводку и плавающую
точку ⚡, достаточно в меню выбрать «⚡ Выбор модели: ВКЛ (выключить)» и
«🙈 Скрыть кнопку ⚡».

Контрольная проверка при желании: открыть ту же сессию в обычном Chrome под тем
же аккаунтом. Если и там список моделей не открывается — флаг точно серверный,
а не особенность WebView.

## 1.9 — почему нажатие ничего не открывает

Диагностика 1.8 выглядела идеально: `⚡ Model [disabled=false]`,
`Обведена кнопка: Model`, `Цель найдена: true`. Но пользователь нажал —
**ничего не произошло**. Разгадка в JS-чанках сайта:

```js
const enabled = !0 === featureFlag("agent-model-selector");
```

Флаг `agent-model-selector` описан в схеме как `boolean()`, но **отсутствует в
серверном RSC-пейлоаде** обеих страниц (`/`, `/agent`) → для этого аккаунта он
`false`. Компонент `ModelSelectorTrigger` получает `triggerDisabled` /
`disabledFlags`, и когда флаг выключен, React **не вешает обработчик открытия**.
Кнопка рендерится, но «пустая»: нашего снятия DOM-атрибута `disabled`
недостаточно — состояние живёт в React, а не в атрибуте.

**Что добавлено в 1.9 (финальная проверка):**

- «🧪 Попробовать открыть (6 способов)»: асинхронно, с паузой 230 мс между
  шагами — `HTMLElement.click()`, mouse-цепочка `pointerdown → mousedown →
  pointerup → mouseup → click`, touch-вариант, `Enter`, `Space`, клик родителя.
  После каждого шага считаются `[role=listbox|menu|dialog]` и
  `[data-radix-popper-content-wrapper]`; результат показывается диалогом и
  копируется кнопкой.
- Инспекция React-props цели (`__reactProps$…`): есть ли `onClick`,
  `onPointerDown`, `onMouseDown`, каков `disabled` в props.
- `elementFromPoint` в центре кнопки — не перекрыта ли она другим элементом.
- Поиск строки `agent-model-selector` в ответе сервера + фрагмент рядом.
- Диагностика выводит все эти поля в читаемом виде.

Если `onClick: false` и флага нет в пейлоаде — вывод окончательный:
**функция выключена серверным фича-флагом, клиентскими средствами её не
включить**. Именно такой и была цель эксперимента — проверить, заработает ли.

## 1.8 — диагностика дала точный ответ

Диагностика из Agent-сессии (`/agent/01a1aacf-…`) показала обе кнопки:

```
• Mode       [BUTTON, disabled=false, popup=null]
• ⚡ Model   [BUTTON, disabled=true,  popup=null]
• Send message [BUTTON, disabled=true, popup=null]
```

То есть **кнопка выбора модели существует**, называется `aria-label="Model"`,
имеет иконку-молнию и реально заблокирована (`disabled=true`). Ошибка была
в приоритете: `exact()` возвращал `button[aria-label="Mode"]` *первым*, поэтому
`unlock()` и фиолетовая обводка доставались селектору режима, а `Model`
оставалась серой. (`Agent mode: false` в диагностике — не ошибка: атрибут
`data-agent-landing` ставится только на `/agent`, а не на `/agent/<id>`.)

**Исправлено:**

- приоритет: точный `button[aria-label="Model"]` → `zap + model` → любая
  `model` → `zap + «A»` → `Mode` как последний запасной вариант;
- вес `model` +16, `mode` снижен с +14 до +3, `modality` по-прежнему −30;
- при каждом `run()` обводка **снимается со всех остальных** кнопок — теперь
  подсвечивается только цель;
- `unlock()` повторно снимает `disabled` при каждом ререндере React
  (MutationObserver без фильтра атрибутов + тик 2 с), так что кнопка не
  «залипнет» обратно;
- диагностика выводит «Обведена кнопка», «Кнопка Model», а также
  `путь /agent` отдельно от `data-agent-landing`.

## 1.7 — обводка не на той кнопке и недоступное меню

Скриншот из чата показал: обведена **✳ (`Modality: Auto`)**, а ⚡A справа
осталась серой. Причина — `modality` давал очки (`+2`), плюс `auto`, `spark`,
`aria-autocomplete`, `data-slot=tooltip-trigger`, и эта кнопка обгоняла молнию.
Это селектор **типа контента**, а не модели.

**Исправлено:** `modality` исключён из кандидатов (`score -= 30` и `continue` в
поиске); добавлен `isZap()` по SVG-пути молнии (`m13`, `13 2`, `l3 14`,
`class*=zap/bolt/lightning`) → `+14`; бонус за отдельную букву `A` в тексте;
приоритетный `exact()`: `button[aria-label="Mode"]` → `Model`/`Mode` →
zap + «A». Диагностика помечает такие кнопки значком ⚡.

**Вторая ошибка — меню было недостижимо.** `onBackPressed()` безусловно вызывал
`web.goBack()`, если `canGoBack()`, а переходы в чате идут через
`history.pushState` → история почти всегда непустая → диалог с диагностикой
не открывался никогда. Теперь:

- крошечная полупрозрачная плавающая кнопка **⚡** справа над композером:
  тап — меню + мгновенный Toast со статусом цели, **долгое нажатие — сразу
  «📋 Скопировать диагностику»**;
- пункт меню «🙈 Скрыть кнопку ⚡» / «👁 Показать кнопку ⚡» (запоминается);
- запасной путь: **двойное нажатие «Назад» за 1,3 с** открывает меню;
- верхней панели / адресной строки по-прежнему **нет**, сайт владеет всем
  экраном — это одна точка 38 dp, а не тулбар.

## 1.6 — почему не работало в Agent mode

`/agent` — **отдельный маршрут**, а не просто переключатель. В его HTML:

- `aria-label="Mode"` (Radix Select: `data-state="closed"`, `aria-expanded`,
  `aria-autocomplete="none"`, `data-slot="tooltip-trigger"`, внутри
  `<span style="pointer-events:none">`);
- нет `Modality: Auto`, нет плейсхолдера «Ask anything»;
- на `<html>` выставляется `data-agent-landing`.

Наш `score()` искал `model / modality / auto`, а слово **«mode» не содержит
«model»** — кнопка не набирала баллов и не попадала в цель. Вторая причина:
переход в Agent mode выполняется через SPA (`history.pushState`), поэтому
`onPageStarted/Finished` не срабатывают и скрипт не перезапускался.

**Исправлено:** точный селектор `button[aria-label="Mode"]` в приоритете,
бонусы за `role=combobox`, `aria-expanded`, `aria-autocomplete`,
`data-slot=tooltip-trigger`; снятие `pointer-events:none` у вложенных
`span/div`; хуки на `pushState/replaceState/popstate`; `MutationObserver` без
фильтра атрибутов (ловит `data-agent-landing`) и постоянный тик раз в 2 с
(только пока вкладка видима); в `PointerEvent` добавлены `button:0, buttons:1`.

В меню: **«🔄 Пересканировать (Agent mode)»**. Диагностика теперь выводит
маршрут, флаг Agent mode и наличие кнопки Mode.

## Почему 1.4 не сработал и что исправлено в 1.5

Причина была **не в сайте, а в моём JS**. При склейке Java-строк получилось:

```js
e.closest('form,textarea,[data-testid*=composer],'+[class*=composer]')
```

`SyntaxError: Unexpected token '*='` — движок не смог разобрать **весь**
`EXPERIMENT_JS`, поэтому он ни разу не выполнился: не было ни обводки, ни
снятия `disabled`, ни MutationObserver. `DARK_JS` идёт отдельным вызовом
`evaluateJavascript`, поэтому тёмная тема продолжала работать и маскировала
проблему. Проверка `node --check` по всем пяти сниппетам сразу это показала.

Исправлено в 1.5:

- опечатка устранена, поиск расширен (`a`, `div[tabindex]`, порог score ≥ 1);
- **[3b/8] в `build.sh`** — `check_js.py` прогоняет `node --check` по каждому
  JS перед компиляцией и **падает сборку** при ошибке;
- `EXPERIMENT_JS` вынесен из-под guard'а тёмной темы и вызывается и в
  `onPageCommitVisible`, и в `onPageFinished`;
- блокировки снимаются через `<style>` с `!important` (надёжнее inline-стилей);
- клик эмулирует полную цепочку `pointerdown → mousedown → mouseup → click`;
- **авто-диагностика**: через 3 с после загрузки Toast «⚡ Кнопка модели
  найдена: …» или «не найдена»;
- **«📋 Скопировать диагностику»** в меню кладёт в буфер список всех кнопок с
  реальными `aria-label`, `disabled` и `aria-haspopup` — можно прислать сюда.

## Что изменилось в 1.4 — эксперимент с выбором модели ⚡A

**Наблюдение.** На пустом экране в композере две иконки, а когда появляется
переписка — добавляется третья: «молния с маленькой буквой A» (селектор модели).
В HTML сайта есть `aria-label="Modality: Auto"` и feature-флаг
`model-selector-featured-models`, то есть селектор моделей реально существует,
но рендерится **лениво**, после загрузки каталога моделей.

**Что сделано в приложении** (только клиентская сторона, серверную логику сайта
не трогаем):

- `EXPERIMENT_JS` после загрузки страницы ищет кнопку по эвристикам
  (`aria-label` / `title` / `data-testid` с `model`, `auto`, `modality`;
  SVG-классы `zap/bolt/lightning/flash`, характерный путь молнии; `aria-haspopup`;
  текст «A»; близость к композеру).
- Снимает `disabled`, `aria-disabled`, `data-disabled`, `pointer-events: none`
  (включая родителей), ставит `cursor: pointer` и рисует тонкий фиолетовый контур,
  чтобы было видно, что кнопка «активная».
- `MutationObserver` + таймер на 60 секунд ловят момент, когда сайт дорисует
  селектор после загрузки каталога.
- В меню (системная «Назад» → когда история пуста) добавлены:
  - **«⚡ Открыть выбор модели»** — программный `.click()` по найденной кнопке;
  - **«🔍 Диагностика кнопки»** — `AlertDialog` с JSON: URL, сколько всего
    кнопок, сколько помечено как активные, найдена ли целевая, список совпадений
    с реальными `aria-label`, `disabled`, `aria-haspopup`;
  - **«⚡ Выбор модели: ВКЛ (выключить)»** — переключатель в `SharedPreferences`,
    при выключении снимает Observers и обводку и перезагружает страницу,
    чтобы сравнить поведение «до/после».
- По умолчанию эксперимент **включён**.

**Чего ожидать.** Если сайт просто скрывает/блокирует кнопку на клиенте — после
нажатия должно открыться его меню выбора модели, и функция заработает внутри
WebView. Если селектор зависит от серверного feature-флага, аккаунта или
registered handlers, меню может не открыться — диагностика покажет, что именно
нашлось. Это и есть суть эксперимента 🙂

## Скачивание с нормальным именем файла

Просмотрщик Arena отдаёт скачанные файлы под своим внутренним ID (`Utfs5jiec2J5aqeWIIXi-maArwMkHoZMoBLqcE3lVQ4`) — это поведение площадки, **не APK**. Обходные пути:

1. **`Arena-download.html`** — автономная страница загрузки (откройте её; работает без интернета). Кнопка использует `download="Arena.apk"` и встроенный data URI, поэтому браузер сохранит файл с правильным именем и расширением `.apk`. Внутри есть:
   - большая кнопка «Скачать Arena.apk»,
   - кнопка «Скачать ZIP» (в архиве лежит файл ровно `Arena.apk`),
   - прямая временная ссылка на файл с `Content-Disposition: attachment; filename=arena.apk`,
   - инструкция по установке.

## Установка

Раз приложение уже стоит — откройте новый `Arena.apk` и нажмите **«Обновить»**. Разрешение «Установка из неизвестных приложений» уже выдано. С компьютера: `adb install -r Arena.apk`.

## Ограничения

- Нужен интернет и свежий **Android System WebView / Chrome**. Без сети — карточка «Нет соединения» с кнопками «Повторить» и «Настройки сети».
- Это обёртка сайта, а не офлайн-ИИ; автоматических обновлений из магазина нет.
- Вход через **Google / Apple** внутри WebView провайдеры иногда блокируют — используйте вход по e-mail или ярлык сайта из Chrome.
- Тема сайта принудительно тёмная: переключение на светлую в настройках arena.ai будет возвращено обратно.
- При самом первом запуске до записи `localStorage` возможна короткая светлая отрисовка — обновите через меню.

## Исходники и пересборка

```
AndroidManifest.xml
src/ai/arena/app/MainActivity.java   логика, тёмная тема, оффлайн-карточка
res/                                 тема, цвета, иконки, строки
icon-space.png                       исходное сгенерированное изображение с космосом
Arena-space-art.png                  чистое квадратное изображение 1024×1024
arena-icon-512.png                   превью иконки приложения 512×512
make_icons.py                        обрезка artwork → все Android-иконки (Pillow)
make_download_page.py                страница загрузки + ZIP
serve_apk.py                         локальный сервер с правильным именем файла
ui-preview.html                      макет полного экрана
build.sh                             полный цикл сборки
arena-release.jks                    ключ подписи (НЕ терять)
```

```bash
./build.sh                      # aapt2 → javac → d8 → zipalign → apksigner
python3 make_download_page.py   # обновить страницу загрузки и ZIP
```

`build.sh` сам докачивает Android build-tools r33.0.2 и `android.jar` platform 33 в **`/tmp/arena-sdk`**, если песочница их сбросила. Это важно: SDK занимает ~386 МБ / ~11 000 файлов, а снимок workspace ограничен 128 МБ / 10 000 файлов, поэтому кэш намеренно лежит вне `/home/user`. Адрес меняется константой `START_URL`, палитра — константами `BG / SURFACE / ACCENT` в `MainActivity.java`.
